This page describes the bounded initial delivery, not completion of the full product vision.

## Evidence and safety boundaries

- Synthetic and recorded labels travel with the source records and each TypedNumber. A geographic
  candidate is a search region; it is not a confirmed bridge. The Nepal demo points are illustrative.
- GET requests inspect the configured store without scoring or modifying it. Verification checks local
  hash consistency and evaluation-ledger links; it is not external attestation against a rewritten store.
- The public view excludes raw model-message blobs, key material and imagery pixels. Evidence is
  metadata-only. Exports preserve metric methods, denominators, intervals, reasons and source labels.
- UI preferences contain display settings only. Private run data is not stored in browser preferences.
- The optional judge panel is restricted to owned public-document traces. Its credential redaction is
  heuristic and cannot classify arbitrary unnamed secrets in prose.

## Kiro and manual acceptance

Build the frontend, replay to a fresh output, then run `treehouse ui serve --store <output>/store`.
For Workshop port preview, bind `--host 0.0.0.0` and supply the exact `--origin https://<preview-host>`
without a path or trailing slash. Browser AWS credentials are never needed.

Check the Book, Sky and Atlas against actual IDs/metrics in the stored records. Exercise direct links,
Story/Developer switching, keyboard selection, 320/390px layouts, 200% zoom, and system reduced motion.
Test with Windows Narrator + Edge and another desktop reader/browser combination. Browser automation
and semantic checks alone do not establish screen-reader conformance or WCAG certification.

Live Bedrock/Strands/Gateway/Runtime behavior, IAM, KB ingestion/citations and costs require actual Kiro
observations. No live cloud success should be inferred from offline tests or a READY resource status.

Known reference examples are excluded from held-out accuracy/calibration, ambiguous split neighborhoods
abstain, and invalid classifier accounting is rejected before budget commits. Process and cost evidence
retains scope/clock/price limitations. These checks do not establish live AWS success, real imagery/model
accuracy, physical measurements or manual Windows accessibility. CI and merge status are recorded in
the pull request/final handoff, not inferred from local results.
