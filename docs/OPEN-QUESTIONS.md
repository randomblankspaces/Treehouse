# Build Design Decisions (formerly Open Build Questions)

> **For agents — what this file is:** Design questions for the build. **Status: decided (SCOPE D25).** Every *recommended default* below is now the decision, with one change: **OQ12's output metric is deterministic, with no LLM judge.** OQ13 doesn't apply (solo build), and OQ14 is still open. Build on these. Change one only by logging a new decision in SCOPE.md.

| # | Question | Decision (accepted default, D25) |
|---|---|---|
| OQ1 | **What a synthetic task contains and what "good workflow" is measured against.** We get no ADB inputs (D13), and an ADB rubric is unconfirmed. | Each synthetic task ships an **expected-workflow spec** listing required and forbidden tools, ordering rules (e.g. "search before fetch"), a step limit, and a "done" condition. A deterministic evaluator checks the trace against it. An optional LLM evaluator rates planning and recovery against a written process rubric, and doubles as the second swappable evaluator (D2) |
| OQ2 | **Which statistics** (D1) | For each configuration: N trials per task (set per eval, default 5). Success rate with a 95% Wilson confidence interval. Mean and spread of steps, latency, cost, errors, and the output metric, with bootstrap 95% CIs. A vs B: permutation test with p-value and effect size. numpy/scipy only. The report states plainly when CIs are wide because N is small |
| OQ3 | **Proving the evaluator works** | An evaluator check: plant known-bad traces (failed tools, loops, wrong order) and known-good ones, then report the detection rate. For the LLM evaluator, re-score the same trace k times and report agreement |
| OQ4 | **How comparisons are designed** (D3) | One baseline plus variants that each change one thing. **Models:** 2 Bedrock models. **Harnesses:** Strands vs. a plain Bedrock Converse tool loop. **Tool sets:** RODA only vs. RODA + 1–2 shortlist servers + LGND embeddings tool. That's 4 configurations; with 5 tasks × 5 trials, about 100 runs, likely under about $30 (confirm on Day 1 from real per-run cost) |
| OQ5 | **Hot-swap evaluator = re-score old runs** | Yes: swapping the evaluator re-scores stored traces without re-running the agent. This is the same code path as replay |
| OQ6 | **What "context given" (D9) records** | Run manifest holds: prompt, system prompt, tool list with exact schemas, MCP server names and versions, model ID and parameters, harness name and version, budget-guard settings, evaluator version, task-spec version, seed |
| OQ7 | **Budget-guard limits** (D6) | Four optional limits: max steps, max tokens, max $, max wall-clock seconds. Hitting one stops the run and logs `budget_exceeded`. The run **counts as a failure** in the stats, not as dropped |
| OQ8 | **Which errors count against the agent** (D12) | All errors are logged and tagged by source. **agent** (bad args, nonexistent tool, loop, giving up) and **tool** (MCP failure or timeout) count against the agent. **infra** (Bedrock throttling, network) is reported but excluded from the agent's score |
| OQ9 | **Which AWS services** (D10) | Bedrock for the agent and LLM evaluator. S3 as an optional run store (local folder by default). CloudWatch/X-Ray as the second tracer. A small CDK stack for the bucket and IAM role (infrastructure as code). Batch trials on Lambda/ECS is a stretch goal |
| OQ10 | **The synthetic tasks** (D13) | 5 ADB-style dataset-build tasks at three difficulty levels: find NAIP imagery for a county; list the open datasets covering an area of interest; build a list of candidate solar-farm sites (with USPVDB as the output answer key); find places that look like a given one, using embeddings; and one deliberately ambiguous task that should trigger errors |
| OQ11 | **Exposing every parameter** (D11) | One run/eval spec schema (a Pydantic model, written as YAML/JSON), served by FastAPI with OpenAPI, so a future UI or the CLI reads every option from that schema |
| OQ12 | **What the output metric is per task, and how it's scored** (D16). D9 said output *quality* doesn't matter, which argues against an LLM quality judge | Deterministic, task-specific checks against its reference (no LLM judge for output): e.g. precision/recall of returned sites vs. USPVDB, or whether the returned dataset IDs are the correct ones for the area. Reported as its own metric next to the workflow scores, never blended into them |
| OQ13 | **Team roles** (D14) | Parked by the team |
| OQ14 | **What does "we have it working" cover?** (round 3) Harness? Tracing? Task generator? The sandbox account? Where is it? | List what already runs, and where, so 06's dependency statuses can be updated |
| OQ15 | **What "tooling" means in "compare harnesses, agents and tooling"** (D3) | MCP tool sets (which servers the agent can use). Tracer and evaluator swaps are covered separately by D2 |
