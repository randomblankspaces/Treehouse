# Independent investigation acceptance criteria

These cases describe observable outcomes. The edge cases are synthetic and are not measurements of a real investigation. They must run offline against the public API, real gateway, sealed store and generated artifacts. A scripted ModelProvider supplies responses; scripts are test inputs, not product policies. The tests should not assume an exact tool sequence, score formula, numeric rating or hidden chain of thought.

1. An injected ModelProvider receives the actual task and tools and can use observations to choose a subsequent action. An action has a prior explicit decision binding the same action ID, tool and parameters; decision evidence must already exist at decision time. The resulting evidence can be cited by claims. Compare runs with equal action counts where one covers informative locations and one repeats a location: the latter must expose its unresolved coverage and missed reference objects. Alternative sequences reaching the same claims and evidence coverage receive the same keyed outcomes.
2. Missing, future, error or blocked evidence cannot support a valid causal link. A decision created after its action, reused for a different action, or mismatched by ID, tool or arguments cannot validate that action. The report identifies the defect rather than inventing a valid chain.
3. The worker sees no reference key, reference labels, key paths, hidden grader notes or completeness mask in system prompt, requests, tool observations or errors. Reference data enters evaluation only after the run is sealed. The model's confidence remains labeled as its own claim, not a keyed accuracy or calibrated probability.
4. The final SQLite and GeoJSON outputs represent actual sealed claims, with their original classes, coordinates, status, confidence and evidence links. No guessed markers are added. Both exports agree on claim identities and geometry. Reject or explicitly report duplicate predictions and out-of-AOI markers; one-to-one class-aware matching prevents duplicates, wrong-class predictions and outside-AOI points from receiving credit.
5. Against a complete synthetic key, independently count true positives, false positives and missed positives; an empty result has false negatives. Against an incomplete key, missing labels alone cannot establish false positives and unreviewed regions must be explicitly marked unknown/abstained. A reference snapshot's provenance and scope are reported, without representing an incomplete public dataset as ground truth.
6. Early completion, max-turns, budget exhaustion, and blocked or denied tools preserve partial work, an explicit stop reason and coverage gaps; denial is not successful evidence. Configuration limits and card scale govern execution rather than a fixed canned task. No budget bypass through decisions.
7. Verify sealed artifacts before evaluation and export. Tampering with a sealed claim, trace, task or manifest makes evaluation fail closed. The original nine replay fixtures and their sealed hashes remain unchanged.
8. Once an independently obtained public labeled snapshot is available, run an actual snapshot case with pinned source, version, license, area and completeness caveat. Synthetic tests cannot substitute for this validation or support claims of real-world geospatial performance.

## Frozen public report contract

All `numbers` entries are JSON serialized Treehouse TypedNumber records. `output.numbers` uses `catalog_tp`, `catalog_fp`, `catalog_fn`, `catalog_precision`, `catalog_recall`; precision and recall carry the corresponding denominator `n`. Only `holdout` features are graded. Duplicate and out-of-AOI predictions cannot gain credit; in complete covered reference evaluation each counts as unmatched. Incomplete references abstain on definitive unmatched-prediction counts and precision. `confidence.numbers.brier` is keyed only for complete valid reference, otherwise abstained or `no_grade_reason` explains unavailability. `process.numbers.decision_coverage` is the fraction of executed investigation actions with a valid prior binding; a count is not evidence of quality. Other diagnostics use actual observations and declare limitations.

Each `decisions[]` item exposes `decision_id`, `action_id`, `tool`, `parameters`, `rationale`, `alternatives`, `confidence`, `parent_id`, `evidence_refs`, `sequence`, `span_id`, `flags`, and `action` (null or `{span_id, result_id, status, tool}`). A `pathways[]` entry has `{decision_id, parent_id, action_id, result_id}` with nulls for missing edges; no edge may be fabricated. Decision rationale is an agent self-report, not hidden reasoning. The opt-in tool must be in the card allowlist. Original runs do not acquire this tool or metadata.

Trusted injected classifier protocol: async `classify(*, window: WindowResult, image: Image, cls: str) -> dict` returns `label`, `confidence`, `explanation`, `model_id`, optional `usage` and `cost_usd`. `classify_window(result_id, cls)` requires prior successful imagery and is opt-in by card; its prediction is model-estimated and cites that result. No key/reference is passed to classifier. Missing usage/cost is unpriced, not zero.
